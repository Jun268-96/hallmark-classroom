# Creation workflow

새 수업 자료를 만들 때 참고한다. 기존 자료를 정리하는 요청에서는 활동·입력·채점 방식을 새로 설계하지 않는다. 이 사례의 네 단계나 색을 다른 수업에 그대로 강제하지 않는다.

## 한 줄 요청에서 완성 파일까지

입력 예:

> 이 스킬로 비례식과 비례배분 수업 자료 만들어줘. 사이트로.

1. **범위:** 별도 학년 지정이 없어 초등 6학년 수준으로 구성한다고 짧게 알린다. 첨부 자료가 없으므로 예제는 직접 만들고 특정 교과서의 원문처럼 제시하지 않는다.
2. **수업:** 비율의 불변 → 비례식의 성질 → 주어진 비로 나누기 → 이해 확인으로 이어진다. 각 활동의 조작 대상과 관찰 결과를 먼저 정한다.
3. **화면:** 상단에 수업 이동, 본문에 활동 질문과 큰 조작 그림, 그림 옆에 입력, 가까이에 상태 피드백을 둔다. 교사 안내는 학생 화면과 분리한다.
4. **구현:** 단일 HTML 안에서 상태·계산·그림·채점을 연결한다. 탭을 눌러도 필요한 입력은 유지하고, 처음부터는 초기값으로 되돌린다.
5. **검사·수정:** 기본값뿐 아니라 값 변경·반례·소수·분수·오류 입력과 모바일을 확인한다. 숫자와 그림이 어긋나면 수정하고 같은 입력으로 재확인한다.
6. **전달:** 작동하는 파일과 검사 범위를 짧게 전달한다. 요청하지 않은 로그인·서버·배포를 제작의 선행 조건으로 삼지 않는다.

위 과정은 6.1 Sol 제작 사례에서 수업 구성·디자인·구현·브라우저 검사·수정을 함께 수행한 절차를 재사용 가능하게 정리한 것이다. 이 문서에 절차를 넣었다는 사실만으로 무료 웹에서 같은 결과를 실험·입증한 것은 아니다.

## 활동별 설계와 확인 값

| 활동 | 구현 | 확인할 입력과 결과 |
| --- | --- | --- |
| 같은 비 | 처음 원액 2·물 3, 두 양을 함께 바꾸는 배수 조작, 물만 1 더하는 비교 버튼 | 2배면 4:6으로 같은 비. 물만 1 더하면 4:7로 달라짐 |
| 비례식 | `a : b = c : d` 입력과 외항 `a×d`, 내항 `b×c` 대응 표시 | 2:3=4:6은 12=12. 4:7로 바꾸면 14≠12. 0.5:1=2:4는 2=2 |
| 비례배분 | 자를 수 있는 리본의 전체 길이와 두 비, 몫에 비례하는 막대 | 전체 40cm, 2:3이면 16cm·24cm. 전체 80이면 32cm·48cm |
| 소수·분수 | 수의 의미를 보존하는 파싱·비교와 단위 표시 | 전체 7.5m, 1:2이면 2.5m·5m. 전체 12cm, 1/2:1/3이면 7.2cm·4.8cm |
| 이해 확인 | 목적이 다른 소수의 직접 구성 문제, 답 확인·풀이·다시 풀기 | 7.5m를 1:2로 나눈 작은 몫에서 2.5와 5/2를 같은 답으로 처리 |

확인 문제는 의미 없이 숫자만 바꿔 늘리지 않는다. 같은 비 찾기, 내항·외항 구별, 빈 항 구하기, 비례배분, 오답의 이유 판단처럼 서로 다른 이해를 확인한다. 문항 수는 수업 범위에 맞춘다.

## 눈에 보이는 결과의 기준

### 주스: 양과 진하기의 구분

- 같은 모양·용량의 곧은 컵을 썼다면 양이 2배일 때 액체 높이도 같은 기준에서 2배로 표시한다. 한 컵만 임의의 고정 높이를 쓰지 않는다.
- 양이 바뀌어도 원액:물의 비가 같으면 진하기는 같다고 표시한다. 물만 더했을 때는 달라진 비와 더 연해졌다는 피드백을 함께 갱신한다.
- 그림이 범위를 넘지 않도록 최대 표시량을 정하고 그 기준을 양쪽 컵에 함께 쓴다. 그릴 수 없는 입력을 조용히 같은 그림으로 뭉개지 않는다.

### 리본: 비의 구획과 길이의 구분

- 전체 막대의 같은 기준에서 두 부분의 길이는 `a/(a+b)`, `b/(a+b)`에 대응한다. `2:3`이면 다섯 구획 중 둘과 셋이 보인다.
- 구획을 표시하면 설명의 ‘비 1’과 같은 기준을 쓴다. `2:4`를 그림만 `1:2`로 약분해 세 칸으로 표시하면서 설명은 여섯 칸 기준으로 두지 않는다. 약분했다면 그림과 설명을 함께 바꾼다.
- 분수·큰 비에서는 지나치게 많은 눈금을 만들지 않는다. 구획선을 생략해도 두 부분의 길이 비와 몫의 라벨은 유지한다.
- 전체를 40에서 80으로 바꾸면 고정된 “40cm 나누기” 제목을 남기지 않는다. 질문·막대 라벨·풀이·검산이 모두 80을 가리켜야 한다.

### 채점: 정답과 표시 상태의 구분

- 숫자는 문자열 모양만 비교하지 않는다. 지원 범위 안에서 `2.5`, `5/2`, `10/4`는 동치인 답이다.
- 0으로 나누는 분수·빈 입력에서 정상 결과나 성공 메시지를 남기지 않는다. 오류 안내 후 올바른 값으로 바꾸면 정상 상태로 복구한다.
- 채점 뒤 답을 고치면 이전 정오답 표시를 해제하거나 새 답으로 계산한다. ‘다시 풀기’는 입력과 피드백을 함께 초기화한다.

## 짧은 화면으로 마무리하기

첫 화면의 예:

```text
[같은 비] [비례식] [비례배분] [확인 문제]

양은 달라도 맛은 같을까?

처음 주스 2:3     =     양을 바꾼 주스 4:6
[같은 기준으로 그린 두 컵]    [배수 조작 · 물만 더하기]

2:3 = 4:6 · 같은 비율이에요.
```

여기에 ‘같은 비 찾기’ 태그, 같은 뜻의 보드 제목, 설명 카드, 중복 단계 번호를 추가하지 않아도 활동은 전달된다. 원액·물의 대응과 배수 조작 라벨은 남긴다. 이 구조는 예시이며 도입 맥락이나 필수 설명이 있는 자료에서 그것을 삭제하라는 뜻이 아니다.

## 실행 환경에 맞는 검증

- 브라우저가 있으면 같은 화면에서 입력을 바꾸고 보이는 값·그림·피드백을 읽는다. 가능하면 1440px와 375px·320px에서 제목, 입력, 이동 버튼, 가로 넘침을 확인한다.
- 코드 실행만 가능하면 계산·채점의 대표값을 실행해 보고 문서 구조를 검토한다. 화면을 본 것처럼 말하지 않는다.
- 실행 도구가 없으면 대표값을 직접 검산하고 이벤트 연결·상태 갱신·초기화를 코드로 확인한다. 파일은 끝까지 제공하되 “브라우저 실행 확인은 하지 못했습니다”라고 구분한다.
- 검사에서 실패한 항목을 수정하고 해당 경로를 다시 확인한다. 이미 통과한 검사만 반복하면서 결과 전달을 미루지 않는다.
